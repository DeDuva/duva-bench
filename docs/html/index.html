DUVA-BENCH · CONTROLLED EXPERIMENTS FOR CODING AGENTS

Leaderboards got crowded.
Answers didn't.

Every published agent score is a joint product of a model, a harness, a toolset, and how deeply the task's language and frameworks sit inside the model's training distribution. Benchmarks collapse that product into one number and rank it. When the number moves, nobody can say which factor moved it — and when a harness is subtly broken, the damage is read as a model deficiency and published as one.

duva-bench runs the experiment instead of the leaderboard: factorial arms → container-isolated trials → verifiable trajectories → pre-registered statistics. Arms are attested, graders are separately authorized, and every result can be re-verified by a third party rather than taken on trust.

01 · WHY

Agent measurement has a confound problem

The field measures agents the way medicine measured drugs before the controlled trial: give the treatment, observe the outcome, publish the number. But an agent result is never one treatment. The model supplies capability; the harness supplies the loop, budgets, and prompts; the toolset supplies the interface; and the task substrate supplies — or withholds — the pretraining familiarity the model leans on. SWE-agent's authors showed the interface alone moves outcomes materially16; Terminal-Bench's authors run every agent through one harness precisely because cross-harness numbers don't compare1; and recent work treats model–harness fit as a first-class research object12.

Our own pilot line paid the tuition four times: a permission filter that left built-in tools reachable manufactured a 72× cross-vendor token gap that one flag reduced to 5.9×; a silent 10-round tool cap read as "a model that gave up"; a path-jail bug made one vendor "produce nothing" for five straight runs; a loop guard raced a budget. Every one of these was invisible from outside, and every one was initially read as a fact about a model. A harness defect is always paid by the provider with less margin — and no leaderboard can see it.

duva-bench exists to solve the problems that follow from taking this seriously — problems no benchmark harness, eval framework, or observability product currently solves together:

ISOLATION

Vary one factor at a time across arms — model, harness, toolset, language, framework, docs quality — with everything else held constant and the constancy checkable: every arm carries a content digest of its harness, tools, and environment, and results refuse to rank across mismatched digests.

VERIFIABILITY

Trajectories are hash-chained per event with drop detection; runs close into a signed attestation binding the arm labels to the trajectory digest and final git state. A reviewer doesn't trust the table — they call GET /verify19.

GRADING INTEGRITY

Graders run under a separate cryptographic identity with tokens stripped from the trial environment; the record shows separately_authorized per score. A run structurally cannot score itself. Unscored is unscored — never zero.

STATISTICAL HONESTY

The analysis is pre-registered in the study spec — primary metric, repetitions, exclusion rules — and digested before the first trial runs. Repeats with a measured noise floor, paired tests, bootstrap CIs over tasks, multiplicity correction. A single-run delta is not a finding here; the pilot that taught us that returned a 3-way tie at n=1 that did not survive n=5.

02 · THE FIRST PROGRAM

Does distribution familiarity beat tooling quality?

duva-bench's founding study program tests one hypothesis: agents working with in-distribution languages, tools, and frameworks outperform agents working with proprietary equivalents, regardless of how good the corresponding skills or MCP tools are. Every enterprise with an internal framework, a house DSL, or a bespoke toolchain is betting real money on the answer.

The instrument is the semantic twin: proprietary arms are isomorphic renames of in-distribution ones — identical semantics, novel surface — so intrinsic difficulty is held constant by construction and the measured gap is the familiarity effect. Twins are regenerated per study so they cannot leak into training data. A documentation-quality sub-axis (none / reference / rich examples, or a full skill) tests the "regardless of tooling quality" clause as a dose–response curve rather than a binary.

Two findings from the literature already discipline the design. First, strong agents route around unfamiliarity: on esoteric languages, frontier agents write Python programs that generate target-language code, and forbidding this collapses their performance3 — so whether metaprogramming is permitted is a pre-registered condition and escape rate is a primary outcome, not noise. Second, the familiarity×capability interaction is the headline, and it may run opposite to intuition: extra resources amplify strong agents' adaptation strategies while leaving weak agents flat3.

The platform outlives the program: any factorial question over agent arms — swarm vs. serial orchestration, provider parity, budget sensitivity — runs on the same machinery.

03 · PRIOR ART

Standing on five research lines — and the gap between them

None of this starts from zero. Five literatures each carry a piece of the question; duva-bench's contribution is the controlled, agentic, verifiable intersection none of them occupies.

COUNTERFACTUAL & PERTURBATION EVALUATION

Wu et al. showed models degrade sharply on counterfactual variants of familiar tasks — 1-indexed Python being the canonical example — separating reasoning from recitation13. ReCode systematized perturbation robustness for code models, including identifier and docstring renames14; GSM1k demonstrated benchmark-overfitting via careful re-instantiation18. Semantic twins are this paradigm, promoted to whole toolsets and frameworks in a multi-step agentic setting.

PRIVATE & UNSEEN LIBRARIES

A multi-year line — TorchDataEval and its siblings9, ExploraCoder's multi-API exploration8, and 2026's "To See is Not to Master," which uses genuinely recent libraries to dodge contamination7 — consistently finds models struggle with private APIs even when the API knowledge is provided in context. Direct single-shot support for the hypothesis; almost none of it is agentic.

UNFAMILIAR LANGUAGES, AGENTIC

The newest and closest line: frontier agents on esoteric languages adapt by metaprogramming, and esoteric-language protocols spread agents that SWE-Bench and Terminal-Bench compress into narrow bands3; inference-time language acquisition is now studied directly4; language choice has been tested at scale5, and token-economics of language choice quantified6. What's missing: isomorphic controls that hold difficulty constant.

SKILLS & DOCUMENTATION COMPENSATION

SkillsBench ran matched skills/no-skills conditions over 7,308 trajectories and 18 model–harness configurations: curated skills gain +16.6pp on average but only +4.5pp on software engineering, and self-generated skills gain nothing10; skill usage in realistic settings is now benchmarked separately11. Retrieval-based compensation goes back to Gorilla17. What's missing: a graded dose–response curve on a controlled substrate — Study D.

HARNESS & INTERFACE EFFECTS

SWE-agent established that agent–computer interface design moves outcomes independent of the model16; Terminal-Bench 2.0 holds the harness fixed across agents for exactly this reason1; HarnessBridge treats the model–harness boundary as a learnable object12; MultiPL-E's language-transfer results anchor the resource-level gradient15. What's missing everywhere: the harness as a controlled experimental factor with attested identity — and any notion of independently verifiable results. That intersection — twin-controlled substrates × factorial harness/model arms × tamper-evident trajectories × pre-registered analysis — is the ground duva-bench is built to hold.

04 · WHY HARBOR + ADP

Borrow the execution. Own the evidence.

An experiment platform needs three layers: something that runs agents, something that records what happened, and something that defines and analyzes the experiment. The discipline is to build only the layer nothing else provides.

Execution: Harbor. Harbor — the harness behind Terminal-Bench 2.01 — provisions a fresh container per trial, injects the agent, and collects execution traces. It already wraps the agents that matter as arms — Claude Code, Codex CLI, OpenHands, Mini-SWE-Agent — runs 32–100 containers in parallel, and defines a task format that 26 existing benchmarks have been adapted into2. We have been down the other road: our pilot line hand-built two in-process agent loops and spent four incident post-mortems learning that every bespoke loop is a source of confounds someone else isn't maintaining. Agent harnesses are treatment arms here, not platform — wrapping real, maintained harnesses is both cheaper and more scientifically honest than running our own.

Recording: ADP. Observability products log trajectories; none make them evidence. ADP19 records per-event hash chains with idempotent-retry and drop detection, closes each run into a DSSE-signed attestation that binds the arm labels to the trajectory digest and the final git sha, stores each score as signed gate evidence with a content-addressed spec and the reporter's identity, and exposes one endpoint — GET /verify — that recomputes all of it on demand. Its consumer contract is already hardened by a prior instrument, adp-replay20, whose live contract suite includes killing the recorder mid-run and tampering with a stored event to prove the verdict degrades to ERROR. No mature alternative offers tamper-evident, third-party-verifiable experiment records. This is the one layer worth owning.

And the reflexive argument. The founding hypothesis predicts that agents build best on in-distribution infrastructure. Harbor's stack — Docker, Python, standard task directories — is exactly that, and Harbor itself is becoming in-distribution as the field adopts it. A platform for testing this hypothesis that ignored the hypothesis in its own architecture would deserve the skepticism it got.

05 · WHAT DUVA-BENCH ADDS

A study is data. A result is a verifiable record.

Everything is drivable three ways — CLI, JSON API, and a web UX for study definition, execution monitoring, and results analysis — and the UX is a client of the same API, never a second path. The pipeline:

Design rules inherited from the projects that came before it — each one bought with a specific failure:

Rank per axis, never blended
A composite score is an editorial, not a measurement. Axes stay separate all the way to the report.
Unscored ≠ zero
A crashed grader leaves a trial unscored; an unpriced model renders unpriced. Nulls never masquerade as measurements.
Digest mismatch ⇒ no comparison
Mid-study grader edits change the spec digest; the analysis refuses to rank across rubrics — or across harness digests.
Amendments stay visible
Pre-registered choices can be amended, but the pre-amendment reading remains computable and every report prints both.
Errors count against the majority
Repetition verdicts fold errors in, not out — a flaky arm can't launder failures into a smaller n.
The record outlives the lab
duva-bench stores nothing ADP can answer. Results are reconstructed from the attested record, not from local state.
